# Chisel Product Polish

_Last updated: 2026-08-12_

Chisel's product direction is **Quiet Precision**: useful actions first, conservative measurement language, local-first privacy, and premium presentation without attractiveness ranking.

## Product hierarchy

### Home

Home is a decision surface, not a dashboard dump. The `Start here` hub exposes four primary actions:

1. **Scan now** — create or compare a baseline when capture conditions are good.
2. **Try-on Studio** — hair, beard, eyewear and makeup decisions.
3. **Face Yoga** — gentle unisex AR movement and posture guidance.
4. **Routine** — controllable actions between scans.

### Analyze

Analyze explains trust before measurement:

- Core analysis runs locally.
- Multi-frame capture is preferred over one selfie.
- Weak pose, lighting, distance or unstable measurements are rejected.
- Results are photographic estimates for within-person guidance, not clinical measurements.

### Try-on Studio

Try-on is decision support. Men hair, Beard Studio, Women hair and Makeup Studio are direct entry points. Controls can collapse so the full face remains visible. Photoreal generation is an explicitly optional cloud feature.

### AR Coach and Face Yoga

The AR camera should look like a premium guide, not a debug mesh. It uses a restrained jaw arc, minimal anchors, form state, clear instructions and a compact glass HUD. Face Yoga is unisex and is described as gentle movement/relaxation awareness, not bone reshaping or spot-fat reduction.

### Grooming / Routine

The default behavior loop is:

1. Choose one area.
2. Follow the routine.
3. Mark it complete.
4. Compare later under matched conditions.

The app rewards consistency rather than repeated appearance checking.

### Progress and results

A missing history is a useful empty state, not a blank region. Chisel asks the user to create one strong baseline first. Result surfaces identify themselves as photographic estimates and encourage matched-condition comparisons.

### Mindset

Affirmation and visualization copy is unisex and calmer. These features are optional confidence/attention practices, not magical guarantees or appearance claims.

### Settings and privacy

Settings lead with `Local by default`. Core analysis stays on-device. Photoreal rendering is optional and is the explicit cloud boundary. Deletion and privacy controls are never premium-only.

### Premium

The paywall must never imply that honest scan results, privacy or deletion require payment. Paid value should come from convenience, advanced progress intelligence, precision capacity, premium style content, professional exports, private-vault options and bounded photoreal cloud rendering.

## Accessibility / interaction rules

- Minimum 44px interactive target.
- Visible `:focus-visible` treatment.
- Large text must wrap instead of clipping.
- Reduced-motion preference disables decorative animation/transition timing.
- Camera and modal layers stay above floating launchers.
- Important destructive actions remain visually distinct and explicit.

## Accuracy language

Do not use `clinical accuracy`, `medical-grade`, `sub-millimeter`, `perfect accuracy`, attractiveness percentiles or guaranteed transformation language. A failed capture should produce correction guidance rather than a result.
