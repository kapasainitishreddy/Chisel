# Personal-photo visual and interaction review

2026-09-10. Reference: the four-screen Chisel concept approved in conversation, `a_polished_high_end_dark_themed_ui_concept_montag.png`. Implementation: exact-source GitHub Actions Chromium screenshots at 360, 430 and 1280px; the final 430px Home/Trainer/Skin/Style views were reviewed together against that concept.

| Comparison | Implementation and intentional adaptation |
|---|---|
| Photo ownership | A real chosen photo supplies the avatar and primary media surfaces. No cinematic stock person is seeded; a natural user photo changes the composition/background. Original file bytes are retained separately from display copies. |
| Palette and surfaces | Near-black/deep-green surfaces, cream pill actions, subdued borders and edge fades follow the approved direction. Photographs are not cosmetically retouched. |
| Home hierarchy | One photo-led first viewport, three balanced launch controls and the real daily task. The existing completion state is retained; no sample progress value is invented. |
| Trainer | Featured personal-photo poster and real Start action, compact thumbnail rows and actual movement counts. Selected-filter contrast and placeholder icons over loaded images were corrected after screenshot review. The photo is not a demonstration of correct movement. |
| Skin | Portrait-first input and short actionable controls; actual results remain hidden until analysis. The framing bracket is decorative, not a detected segmentation map. No fictional skin scores from the concept are seeded. |
| Style | Category filters connect to existing live guides. The still photo is explicitly not style-applied; no fake photoreal thumbnails or generated results are shown. Double scroll spacing exposing previous content was corrected. |
| Copy and spacing | The approved Home heading and short task labels are retained. Original experimental/safety/consent information remains available, mostly in existing disclosures. Phone gutters, tile widths, button positions, typography and scroll alignment were inspected. |
| Navigation | Existing five primary routes and modal tool surfaces are preserved rather than copying nonfunctional navigation from the concept. These are code-native controls, not a screenshot layer. |

The reference is a four-screen presentation board, not a native single-screen screenshot. Final implementation inspection used 430x900 browser frames rather than claiming pixel-identical board dimensions. No claim of perfect visual fidelity, full accessibility conformance or user-approved final aesthetics is made. Functional browser tests are not aesthetic or accuracy certification.
